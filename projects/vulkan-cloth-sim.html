Vulkan Compute Shader Cloth Simulation

Overview

This project was a collaboration between me and Claire Ogawa for the final project of CSC 572 Graduate Computer Graphics. The intention was to build a realtime enviroment using the Vulkan Graphics Library, and to use a compute shader to create a simple cloth simulation. This was the first time either of us used vulkan, and so setting up the project from scratch was a massive, multi week long task.

Cloth simulation has traditionally been done using many different methods. One of the most efficient methods used in modern graphics programming is the utilization of GPU side compute shaders to calculate the physical interactions for a simulated cloth plane. Compute shaders can be implemented with every industry standard modern graphics library, and for this project we adapted the work of Va Hongly, Min-Hyung Choi, and Min Hong in Vulkan.

Cloth simulation is important for modeling garments in media, like films, video games, contributing to both realism and stylistic rendering. Modeling this behavior contributes to scene aesthetics, immersion, and believable physics interactions. It is implemented using “the mass-spring system,” and both implicit and adaptive constraints [6]. Our project will implement these physics mechanisms using compute shaders to construct a believable cloth simulation.

How it works

This project takes a plane and texture, applies according transforms, and runs through a shader pipeline to simulate cloth motion. The Shader takes data in the form of a UBO (Uniform Buffer Object) full of simulation parameters, then transforms the cloth based on its position, velocity, and spring constrains from the previous frame.

The use of the compute shader makes the simulation extremely performant on dedicated GPU hardware in real time. We included texture mapping and a key to flip the gravity and rotate the object to observe the results from different angles.

What is a compute shader?

A compute shader is an optional extra step in a graphics pipeline that uses the power of the gpu for calculations or other operations. It has a lot of use cases, as it is optimized for parts of a real time program that aren't coloring fragments or moving vertices around. There are other shaders in this vain like geometry shaders and tesselation shaders! Compute shaders are just the most versitle of them.

After submission

Later on I wanted to have a solid base project to build a vulkan application around, but there was one problem. A 5 week vulkan application had many problems, the main one being file organization. Just about every part of the application was found in our nearly 3k lines of code in our main file (Yucky). I went ahead and spent a couple days refactoring the megafile into their own classes and files.

Reflection and future work:

There we're two reasons we had for choosing this as the final project for the class:

first I wanted to build an understanding with hands on experience of Vulkan as a graphics library. Why would you want to use it? What are its advantages/disadvantages? How is it different from OpenGL? Should you use it for a project like this? I definately got the answer, that it is not built for this kind of project. Not that it didnt work, it was very performant and the project as a whole was a success, but the amount of set up it takes to even draw a single triangle is massive in Vulkan. This is very intentional, as it gives you fine tuned control over every piece of the engine! This is where the advantages are, lower driver overhead, fine tuned decisions for performance, perfect for a large game engine or real time application! But our project was small and simple, ergo not really the tool for the job. I was really glad I chose to do it despite this, since it gives me the context as to why!

The second reason I chose this project was to build a cloth simluation and learn compute shaders. The compute shaders were definately used and very cool to learn! The cloth simulation worked, and thats about all that I can say about it positivly. Most of the time went into building a developing a full Vulkan renderer in 5 weeks, which was a much bigger task than initially expected. The cloth simulation was kind of neglected as the final product, we didn't have a chance to dive into the more interesting problems of one like self intersections.

Future work would be to implement some form of self intersection checking, some thickness to the cloth, and the ability to incorporate it into a larger game engine situation. Even with all its problems, this project was a fantastic learning experience!
